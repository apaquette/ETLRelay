    Defect found and corrected¶

    Previously, the native Parquet writer's context-manager exit could replace an upstream processing error with an error writing the footer. A regression test reproduced this against a real PyArrow writer and a deterministic failing stream.

    ParquetWriter now explicitly attempts finalization after failure, retains the original exception, and logs a secondary finalization error using its type only. A finalization error after otherwise successful serialization still propagates. There is no public signature, configuration-schema, or CLI exit-code change.

    This does not make file output atomic. A failed footer may leave unreadable output. Successfully finalized earlier batches may remain readable after an upstream failure; they are still partial results from a failed run.

    Test design and limits¶

    • Permission failures use patched file opening rather than chmod assumptions; behavior stays deterministic under privileged users and across platforms.
    • Connection refusal uses SQLAlchemy engine doubles rather than external services. Actual SQLite syntax and transaction failures use local databases.
    • The processor/output test uses a two-batch reader double and real CSV/Parquet serialization, retaining stream references so garbage collection cannot hide missing cleanup.
    • Normal-path stream, SQL result/connection, and engine cleanup tests remain in place. New assertions supplement those existing tests rather than duplicating a complete source/sink combination matrix.
    • Redaction evidence concerns ETLRelay-controlled diagnostics. Native library exceptions can contain sensitive data; arbitrary third-party exceptions, application handlers, filenames, and configuration keys are not universally sanitized. Test sentinels do not establish universal sanitization.
    • Resource release means closure/disposal is attempted at the owning boundary. A failing underlying close/dispose operation cannot be guaranteed to release an external resource. The tested contracts establish exception precedence and continued cleanup attempts where documented.

    The Parquet precedence defect is addressed in this change. No other unresolved release-blocking defect was identified by this audit. Required CI and integration into dev remain prerequisites for closing the ticket. Supported-platform installation verification remains assigned to 0.9.0-06.
