    API Reference¶

    This reference is generated from the public code and its docstrings. The configuration APIs introduced in ETLRelay 0.6.0 are listed separately from the direct runtime component APIs.

    Configuration loading and validation¶

    validate(config) ¶

    Validate the root schema and all present pipeline sections.

    The root value must be a mapping with string keys. The supported top-level fields are version, source, processors, and sink, and all four fields are required. The version must be the integer specified by SUPPORTED_VERSION.

    After checking the root mapping, this method delegates validation of each present pipeline section and aggregates the reported errors. Root values that are not mappings, or mappings containing non-string keys, are rejected before section validation begins.

    etlrelay.readers.yaml.YamlReader ¶

    This reader handles safe YAML parsing and enforces the root mapping contract. It does not validate application-specific schema rules or restrict the key types of nested mappings.

    The catalog registers CSV and Parquet readers and writers, local filesystem storage, file and SQL sources and sinks, and the select_columns, rename_columns, and filter_rows processors. It also assembles the dispatchers and root configuration validator.

    A single set of registries is shared between the corresponding validators and factories, and the same SQL engine factory is supplied to both SQL component factories.

    etlrelay.config.pipeline_builder.PipelineBuilder ¶

    Build runtime pipelines from validated configuration mappings.

    The builder resolves source, processor, and sink registrations before invoking component factories. SQL environment references are preflighted before component construction to prevent missing or empty environment variables from causing partial pipeline construction.

    getenv provides a lightweight environment lookup for isolated builder use and tests. In the default application composition, the shared SqlEngineFactory should be supplied so successful preflight makes resolved connection URLs available to SQL component factories.

    The builder does not execute the pipeline it constructs. When a shared SQL engine factory is supplied, the caller is responsible for closing the builder after pipeline execution to release the factory's resources.

    etlrelay.config.sql_engine_factory.SqlEngineFactory ¶

    Resolve SQL connection URLs and manage SQLAlchemy engine lifecycles.

    Environment-variable references must pass preflight before engines can be created. Successful preflight stores resolved connection URLs without creating engines. Engines are created on demand and cached by environment variable name.

    The factory owns the engines it creates and disposes of them when close() is called. Closing also discards resolved connection URLs. Environment lookup and engine creation can be injected for testing.

    preflight(references) ¶

    Resolve and validate all referenced connection environment variables.

    The mapping associates configuration paths with environment-variable names. Each unique variable is read once, and missing or empty values are aggregated into a single error. No engines are created during preflight.

    A successful preflight replaces any previous resolved URL set. A failed preflight leaves resolved URLs unavailable for engine creation. Preflight cannot be repeated while the factory has active engines.

    Parameters:

    Name Type Description Default
    references Mapping[str, str]

    Mapping from configuration paths to environment-variable names that provide SQL connection URLs.

    		 required

    Raises:

    Type Description

    Note

    Exceptions raised by the environment lookup callable are treated as missing environment-variable values. Error messages do not include resolved URLs or environment lookup exception details.

    create(variable_name) ¶

    Create or retrieve the engine for a successfully preflighted variable.

    Engines are created on demand and cached by environment-variable name. Subsequent requests for the same name return the cached engine rather than creating another instance.

    Parameters:

    Name Type Description Default
    variable_name str

    Name of the environment variable whose connection URL was resolved during successful preflight.

    		 required

    Returns:

    Type Description
    Engine

    The cached SQLAlchemy engine for the variable, or a newly created
    Engine

    engine that is stored for subsequent requests.

    Raises:

    Type Description
    SqlEngineFactoryError

    close() ¶

    Dispose of owned engines and discard resolved connection URLs.

    Engine disposal is attempted in reverse creation order. The factory clears its engine cache and resolved URLs before disposal, and continues disposing remaining engines if one fails. Calling this method more than once is safe.

    Raises:

    Pipeline¶

    etlrelay.pipeline.pipeline.Pipeline ¶

    Coordinate batch processing between a source, processors, and a sink.

    The pipeline obtains batches from a source, applies each configured processor in sequence, validates the resulting output schemas, and passes compatible batches to the sink.

    The first processed output batch establishes the expected schema for the run. Subsequent output batches must have matching field names, field order, Arrow types, and nullability. Schema metadata differences are ignored. Zero-row batches participate in schema validation.

    Processing is lazy and does not buffer all batches before writing. If a later batch has an incompatible schema, a ValueError is raised before that batch is yielded to the sink. Batches successfully written before a later failure are not rolled back.

    Exceptions from the source, processors, or sink otherwise propagate to the caller.

    __init__(source, processors, sink) ¶

    Initialize the pipeline with its source, processors, and sink.

    Parameters:

    Name Type Description Default
    source Source

    Component that produces batches for processing.

    		 required
    processors Sequence[Processor]

    Ordered sequence of processors to apply to each batch. May be empty if no transformations are required.

    		 required
    sink Sink

    Component that consumes the processed batches.

    		 required

    run() ¶

    Execute the pipeline and deliver processed batches to the sink.

    Batches are obtained from the source, processed in sequence, and passed to the sink as an iterable. Processing is lazy, avoiding buffering all batches in memory before writing. If the source produces no batches, the sink is not called.

    Raises:

    Type Description
    ValueError

    If a processed batch has a schema incompatible with the first processed output batch.
    Exception

    Exceptions raised during source iteration, processing, or sink execution propagate to the caller.

    Previously written batches are not rolled back if a later batch fails.

    etlrelay.processors.select_columns.SelectColumns ¶
